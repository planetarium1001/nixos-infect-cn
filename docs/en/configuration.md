# Configuration

[中文](../zh-CN/configuration.md) | English

This page explains where the generated configuration comes from, the three ways to change it, every placeholder, and common customization patterns.
The goal is to have `/etc/nixos` shaped the way you want it before installation starts.

## Where the configuration comes from

- It inherits the hostname (`hostname -s`) and domain (`hostname -d`) of the previous system by default.
- It generates `configuration.nix` and `hardware-configuration.nix`; `networking.nix` is added when a static network is detected.
- OpenSSH, `boot.tmp.cleanOnBoot` and zram swap are enabled by default, and `system.defaultChannel` plus domestic substituters are written.
- Root's public keys are collected from `/root/.ssh/authorized_keys`, `/home/$SUDO_USER/.ssh/authorized_keys` and `$HOME/.ssh/authorized_keys`, in that order.
- Default packages: `vim`, `git`, `curl`, `wget`, `htop`, `tmux`; `system.stateVersion = "25.11"`.
- With a real swap partition it switches to `swapDevices` and no longer enables zram; `cache.nixos.org` is never written into the config.

## Method 1: interactive mode

**Use interactive mode when you want to change Nix files**; piped execution has no terminal, so every prompt takes its default. Editing `hardware-configuration.nix` directly affects the boot loader, so do not change it if you are unsure of the consequences.

```bash
curl -fsSL https://cdn.jsdelivr.net/gh/planetarium1001/nixos-infect-cn@master/nixos-infect.sh -o nixos-infect.sh
bash nixos-infect.sh --interactive --lang=zh
```

The flow has five steps:

- Probe the mirrors and show the summary table.
- Three choices: installer mirror, channel mirror, binary cache priority.
- Show the configuration summary.
- Answer `n` to open a shell under `CONFIG_DIR` (default `/etc/nixos`) and edit `configuration.nix`; `exit` returns.
- The summary re-reads the file contents, and installation starts once you confirm.

## Method 2: external templates

`--template=TYPE:PATH` replaces a built-in template with an external file, and can be given more than once.

| TYPE | Target file | Purpose |
| --- | --- | --- |
| `configuration` | `/etc/nixos/configuration.nix` | Main system configuration |
| `hardware` | `/etc/nixos/hardware-configuration.nix` | File systems and boot |
| `networking` | `/etc/nixos/networking.nix` | Static network |

```bash
bash nixos-infect.sh --lang=zh \
  --template=configuration:/root/my-configuration.nix \
  --template=networking:/root/my-networking.nix
```

- `PATH` is a path on the machine running the script; if the file is unreadable the script errors out at once.
- `@@NAME@@` in a template is substituted; dropping the placeholders and writing static content directly works too, since the script only does text substitution.
- Types without `--template` still use the built-in template.

## Method 3: editing the built-in templates

- The built-in templates live in `SECTION 11` of the script, four blocks in total: `TMPL_CONFIGURATION`, `TMPL_HARDWARE_EFI`, `TMPL_HARDWARE_BIOS`, `TMPL_NETWORKING`.
- Editing these `cat <<'TMPL_EOF'` blocks changes what is generated by default.
- Changes ship with the script and must be merged again on upgrade, which makes them easy to lose; prefer external templates in ordinary cases.

## Placeholder reference

### configuration template

| Placeholder | Meaning | Example value |
| --- | --- | --- |
| `@@HOSTNAME@@` | Short hostname of the previous system | `VM-0-9-opencloudos` |
| `@@DOMAIN@@` | Domain of the previous system, usually empty | `""` |
| `@@ZRAM@@` | Whether zram swap is enabled | `true` |
| `@@NETWORK_IMPORT@@` | Whether `networking.nix` is imported | `./networking.nix` |
| `@@SUBSTITUTERS_BLOCK@@` | The whole `nix.settings.substituters` block | `nix.settings.substituters = [ ... ];` |
| `@@DEFAULT_CHANNEL@@` | URL of `system.defaultChannel` | `https://mirrors.tuna.tsinghua.edu.cn/nix-channels/nixos-25.11` |
| `@@AUTHORIZED_KEYS@@` | Root public keys, multi-line, each line quoted | `"ssh-ed25519 AAAA... me@laptop"` |

### hardware template

| Placeholder | Meaning | Example value |
| --- | --- | --- |
| `@@ESP@@` | ESP partition in the EFI case | `/dev/disk/by-uuid/1234-ABCD` |
| `@@GRUBDEV@@` | Disk GRUB is written to in the BIOS case | `/dev/vda` |
| `@@ROOTFSDEV@@` | Root file system device | `/dev/vda1` |
| `@@ROOTFSTYPE@@` | Root file system type | `ext4` |
| `@@SWAPCFG@@` | Written when a swap partition already exists | `swapDevices = [ { device = "/dev/vda2"; } ];` |
| `@@AVAILABLE_KERNEL_MODULES@@` | initrd kernel modules | `"ata_piix" "uhci_hcd" "xen_blkfront"` |

### networking template

| Placeholder | Meaning | Example value |
| --- | --- | --- |
| `@@ETH0_NAME@@` | Interface carrying the default route | `eth0` |
| `@@ETH0_IP4S@@` | IPv4 addresses (Nix attribute list) | `{ address="192.0.2.10"; prefixLength=24; }` |
| `@@ETH0_IP6S@@` | IPv6 addresses, may be empty | `{ address="2001:db8::10"; prefixLength=64; }` |
| `@@GATEWAY@@` | IPv4 default gateway | `192.0.2.1` |
| `@@GATEWAY6@@` | IPv6 default gateway | `2001:db8::1` |
| `@@ETHER0@@` | Interface MAC address | `52:54:00:12:34:56` |
| `@@NAMESERVERS@@` | DNS taken from `/etc/resolv.conf` | `"8.8.8.8" "1.1.1.1"` |
| `@@PREDICTABLE_INAMES@@` | Forced setting for the interface naming policy | `usePredictableInterfaceNames = lib.mkForce false;` |

## Common customization examples

### Add a system user

```nix
users.users.alice = {
  isNormalUser = true;
  extraGroups = [ "wheel" ];
  openssh.authorizedKeys.keys = [ "ssh-ed25519 AAAA... alice@laptop" ];
};
```

- Add it at the top level of `configuration.nix`; the `wheel` group can run `sudo`, and remember to set a password for the user as well (`passwd alice`) or configure a public key.

### Enable flake support

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

- Add it at the top level of `configuration.nix`; the script still builds the system with channels and does not generate `flake.nix`, so the migration is up to you.

### Pin a static IP

```nix
networking = {
  useDHCP = false;
  interfaces.eth0.ipv4.addresses = [
    { address = "192.0.2.10"; prefixLength = 24; }
  ];
  defaultGateway = "192.0.2.1";
  nameservers = [ "223.5.5.5" "119.29.29.29" ];
};
```

- Write it at the top level of `configuration.nix`, and do not import the generated `networking.nix` at the same time; pick one of the two.
- Confirm the interface name with `ip address show` first; alternatively let the script generate `networking.nix` (`--networking`) and edit that.

### Append SSH public keys

```nix
users.users.root.openssh.authorizedKeys.keys = [
  "ssh-ed25519 AAAA... ops@bastion"
  "ssh-ed25519 AAAA... old-key"
];
```

- The template generates the whole list from the previous system's `authorized_keys`, so a manual rewrite replaces the entire list; to keep old keys, add the new lines to that list, or keep `@@AUTHORIZED_KEYS@@` in an external template and append after it.

### Replace substituters and channel

```bash
NIX_SUBSTITUTERS="https://mirror.example.edu.cn/nix-channels/store" \
NIX_CHANNEL=nixos-25.11 \
NIX_CHANNEL_URL="https://mirror.example.edu.cn/nix-channels/nixos-25.11" \
bash nixos-infect.sh --lang=zh
```

- Environment variables take precedence over probing results; `NIX_SUBSTITUTERS` is space-separated, and the script deduplicates it and filters out `cache.nixos.org`. To pin only the channel version, use `--channel=nixos-25.11`.
- After conversion you can also edit `configuration.nix` directly and run `nixos-rebuild switch`:

```nix
nix.settings.substituters = [
  "https://mirrors.tuna.tsinghua.edu.cn/nix-channels/store"
  "https://mirror.nju.edu.cn/nix-channels/store"
];
system.defaultChannel = "https://mirrors.tuna.tsinghua.edu.cn/nix-channels/nixos-25.11";
```

## Why the summary reads from the file

- In interactive mode you may have edited `configuration.nix` in the shell, so the summary must not keep showing stale values from the script's memory.
- The summary uses `cfg_file_get` to read back `networking.hostName` and `system.defaultChannel`, and `cfg_file_substituters` to read back the substituters list; only when a read fails does it fall back to the probed values.
- The summary is therefore the configuration about to be installed: keep editing while it does not match, and it refreshes again after `exit`.
